# Auto-Coder 核心模块文档生成计划

## 背景

基于对 `autocoder/sdk` 模块的分析，我们识别出了支撑SDK工作的核心模块和重度依赖项。这些模块需要优先生成 `.ac.mod.md` 文档，以便开发者理解整个系统的架构和工作原理。

## 核心模块依赖分析

### SDK 直接依赖的核心模块

从 `src/autocoder/sdk/__init__.py` 和 `src/autocoder/sdk/core/bridge.py` 的分析中，我们识别出以下核心依赖：

1. **auto_coder_runner** - 核心运行器模块
   - `run_auto_command` - 执行自动编码命令
   - `configure` - 配置管理
   - `init_project_if_required` - 项目初始化
   - `load_tokenizer` - 加载分词器
   - `start/stop` - 引擎生命周期管理
   - `commit` - 代码提交功能
   - `get_memory/save_memory` - 内存管理
   - `get_final_config` - 配置获取

2. **rag.variable_holder** - 变量持有器模块
   - `VariableHolder` - 全局变量管理

3. **utils.llms** - LLM工具模块
   - `get_single_llm` - 获取LLM实例

### 事件系统相关模块

从bridge.py的事件转换逻辑中，我们可以推断出以下事件相关模块：

4. **events** - 事件系统模块
   - 各种事件类型定义（LLMThinkingEvent, ToolCallEvent等）
   - 事件管理和分发机制

### 间接但重要的依赖模块

基于SDK的功能和使用场景，以下模块也是核心依赖：

5. **common** - 通用工具模块
   - `AutoCoderArgs` - 参数定义
   - 文件操作工具
   - 配置管理工具

6. **chat** - 聊天功能模块
   - 对话管理
   - 命令处理

7. **plugins** - 插件系统模块
   - 插件管理器
   - 插件接口定义

## 文档生成优先级

基于依赖关系的重要性和复杂度，建议按以下优先级生成文档：

### 第一批（核心基础）
1. **auto_coder_runner** - 最核心的运行器，SDK的主要依赖
2. **common** - 基础工具集，被广泛使用

### 第三批（扩展功能）

## 生成任务 Prompt

你需要按照以下步骤为每个模块生成 `.ac.mod.md` 文档：

### 任务说明

请按照 `specs/ac_mod.md` 中定义的规则和要求，为以下模块生成对应的 `.ac.mod.md` 文档。每个文档都应保存在 `specs/` 目录下，文件名为 `[模块名].ac.mod.md`。

### 当前任务模块

**模块路径**: `src/autocoder/[模块名]`

### 执行步骤

1. **创建任务清单**
   使用 `todo_write` 创建任务清单，保存在 `specs/jobs/todo-list-[模块名].md`

2. **探索模块结构**
   - 识别模块类型（包模块 vs 单文件模块）
   - 列出所有文件和子目录
   - 理解模块的整体组织结构

3. **分析核心功能**
   - 读取主要文件内容
   - 识别关键类、函数和常量
   - 理解模块的设计理念和用途
   - 查找使用示例和测试用例

4. **识别依赖关系**
   - 分析导入语句
   - 识别对其他模块的依赖
   - 查找被其他模块依赖的情况
   - **🔥 重要**：必须通过实际代码验证，使用以下方法：
     - `grep_search(query="from [模块路径]|import.*[模块名]", include_pattern="*.py")` - 验证实际导入
     - `grep_search(query="from [当前模块路径]|import.*[当前模块名]")` - 验证被依赖情况
     - `grep_search(query="[主要类名]|[主要函数名]", include_pattern="*.py")` - 验证具体使用
   - **避免推测**：所有依赖关系必须有具体代码引用支撑

5. **编写文档**
   - 选择正确的文档模板（包模块/单文件模块）
   - 按照标准结构编写各个章节
   - 提供实用的代码示例
   - 绘制清晰的依赖关系图

6. **质量检查**
   - 验证所有代码示例的正确性
   - 确保路径引用的准确性
   - 检查文档的完整性和一致性

### 特别注意事项

1. **SDK依赖的核心模块**需要特别详细地说明其与SDK的关系
2. **事件系统**需要清楚地说明各种事件类型和事件流
3. **配置管理**相关的模块需要说明配置项和使用方式
4. **工具类模块**需要提供丰富的使用示例
5. **🔥 依赖关系验证**：基于本次 auto_coder.py 文档生成的经验教训
   - **必须通过实际代码分析**：使用 `grep_search` 查找真实的导入和使用关系
   - **避免基于推测的依赖描述**：所有依赖关系都需要具体的代码引用支撑
   - **提供具体使用场景**：说明在什么文件的什么情况下使用了该模块
   - **区分直接和间接依赖**：明确标注依赖的类型和层级

### 开始执行

请从 **auto_coder_runner** 模块开始，这是整个系统的核心运行器，也是SDK最重要的依赖。
